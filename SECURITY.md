# Security policy

Murmur's proposed first release is source-only v0.1.0 for Apple Silicon macOS. No supported binary release is claimed here. Security fixes and support windows are not yet promised.

**Do not open a public issue for a vulnerability.** Issues, comments and attachments are public. Never post transcripts, recordings, API keys, signing material, logs containing personal data, or details that expose someone else's system. Do not upload a diagnostic report without reading and redacting it yourself.

Once **private vulnerability reporting is enabled and verified** for this repository, use its **Security → Report a vulnerability** button. Give minimal reproduction steps with synthetic data, affected version/commit and potential impact; do not attach real user data. Until that private route is enabled and verified, the owner must publish and verify an alternative private contact route before directing people to submit security details. Do not send security details to the public issue form or the provisional in-app report link.

**Owner-only setup, not done by this file:** in the public GitHub repository, an owner/admin goes to **Settings → Security → Code security and analysis → Private vulnerability reporting → Enable** (confirm the exact current UI in [GitHub's instructions](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository)). Verify from a separate account that the private report option appears before announcing it. A `SECURITY.md` alone does not turn the feature on.
