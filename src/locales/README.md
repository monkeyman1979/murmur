# Interface language catalogs

Murmur offers English, Spanish, French and Russian for **trial** on the first onboarding screen and in Settings → General → App language. Both selectors share the same saved preference and change the interface immediately without adding an onboarding step. This preference changes interface copy in the main, indicator and meeting-controller webviews, native tray labels and fixed notifications. Dictation and new meetings always use Whisper Auto-detect; the interface preference does **not** translate or rewrite saved transcripts. No additional language model is required.

- `en.json` is the English source catalog; `es.json`, `fr.json` and `ru.json` contain matching keys and interpolation parameters. Unexpected missing keys fall back to English, but `src/i18n/catalogs.test.ts` fails on catalog omissions and unknown literal message keys. It also scans Vue templates for unlocalized visible and accessible copy outside third-party UI primitives and proper names.
- `src/i18n/index.ts` registers the four catalogs; `src/i18n/appLanguage.ts` stores the interface preference in `murmur:app-language` and resolves stale/unknown values to English. `src/main.ts` installs i18n in all webviews; `src/App.vue` mirrors it to the native status item. New copy should always be added to all four catalogs and tested before shipping. The long default Copy for AI instructions live in `src/composables/useMeetingAiHandoff.ts` (English) and `src/composables/meetingAiHandoffDefaults.ts` (Spanish, French, Russian). Only an unsaved default follows App language: a saved custom prompt, in any language, remains verbatim across App language changes; Restore default uses the current App language. Preserve `{{TRANSCRIPT}}` exactly once and keep the metadata key `current_title` and generic `Meeting YYYY-MM-DD HH:mm` title shape unchanged in every prompt. These are prompts for an external AI after the user pastes the clipboard, not transcript translation.
- Frontend runtime errors are localized using message keys. Backend diagnostics, device names, paths and transcript contents are not translation resources; never expose raw exceptions or user content to notification catalogs. `src-tauri/src/native_language.rs` translates tray commands and `src-tauri/locales/native_notifications.json` translates fixed native notifications. macOS-owned permission UI follows the system's preferred language; localized `InfoPlist.strings` provide the app's explanation.
- Rich sentences with links and formatted spans use `<i18n-t>` instead of concatenated translated fragments. Locale-aware number, date and duration formatting lives in `src/lib/format.ts` and quantity forms in `src/i18n/plurals.ts`.

Run `corepack pnpm build`, `NODE_OPTIONS=--no-experimental-webstorage corepack pnpm test:unit`, and `cd src-tauri && cargo test --lib`. Before calling translations production-quality, arrange independent fluent review of terminology, plurals and privacy wording and inspect **each** language on an installed signed app: onboarding, permissions, Settings, Home, Dictations, Meetings, Dictionary, controller, indicator, tray, toasts, native notifications, keyboard/VoiceOver, long-text layout and Cyrillic glyphs. Automated parity and unit tests do not replace this installed-app QA. The Settings → Dictation language dialog groups the pinned Whisper Small Multilingual model's 99 language tokens into four languages that also have trial App interface translations and 95 model-only languages. The plain-language headings distinguish App + dictation + new meeting transcripts from dictation + new meeting transcripts only; the dialog explicitly states that transcription accuracy has not been tested language by language for either group. New meetings use the same model with Auto-detect and have no separate language-quality certification. Language names are formatted by `Intl.DisplayNames` for the current App language. This is informational and never changes the transcription language. See `docs/APP-LANGUAGE-AUDIT.md` for the trial evidence and remaining manual checks.
