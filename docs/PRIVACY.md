# Murmur privacy notes

Settings → General → Meeting captures includes optional Calendar accounts setup. Clicking Connect calendars requests macOS calendar Full Access if needed, then lists email-labelled accounts through EventKit, including Google accounts synced into Apple Calendar. One checkbox selects an account and all its calendars, including newly synced calendars in that account. No account is selected by default. Event queries cover only selected accounts’ calendars for the next seven days; an empty selection reads no events. EventKit has no dedicated login-email field: the display label uses an explicit email in the source title, or one unambiguous exact email label among that source’s calendars. Labels are not authentication identities; selection uses EventKit’s source identifier. Unidentified sources, local calendars, birthdays and subscription-only sources are not account choices. Murmur does not access private Apple account databases or account credentials. Opening Settings alone does not request access or read events. Apple provides no read-only permission tier, but Murmur does not write calendar data. Account email labels appear only in the settings account-selection panel, opened with Manage accounts; Refresh and Disconnect calendars live inside that panel. Account management reads only the account directory, not events. Event titles/times appear only in the floating reminder; invite notes and URLs are used locally to recognize meeting providers and are not returned to the UI. Meeting reminders are a separate opt-in, off by default. Once enabled, Murmur checks the selected accounts locally about every 15 seconds while running, including when Settings and the main window are hidden. The main webview remains runnable while hidden so it can durably acknowledge reminders before display. The saved reminder timing can be At meeting start, 15 seconds, 30 seconds or 1 minute before (default 15 seconds). For already-synced meetings, the native scheduler wakes at the selected deadline between regular refreshes; sleep or delayed account synchronization can still delay a reminder. It offers a nonactivating floating prompt at the selected time, never starts recording automatically, and routes an explicit Start recording click through the existing recording-notice, permission, model, and capture-admission checks. The prompt expires at the meeting’s end or two minutes after its scheduled start, whichever comes first. Old meetings are not backfilled when reminders are enabled; a meeting missed during a long sleep may produce no prompt. Active meeting capture suppresses prompts. The settings account directory is kept only in memory and cleared on Disconnect, a failed refresh, or leaving General settings. While reminders are enabled, native code may retain an upcoming offer in memory until dismissal, expiry, cancellation or disablement. Disconnect turns reminders off but does not revoke the OS grant, which you can revoke in System Settings. Calendar connection status, selected EventKit account/source identifiers, and reminder opt-in/timing are saved locally in Murmur’s settings; email labels, event titles, and event notes are not persisted by this feature. Turning reminders off keeps the calendar connection and account selections; reopening Settings does not reread the account directory until you choose Manage accounts. Earlier debug per-calendar preferences are not automatically converted into whole-account consent. A SHA-256 occurrence key and expiry (about 24 hours after scheduled start) are saved locally before a reminder is displayed, so showing/dismissing a prompt does not repeat it after restart. These entries contain no title, email, invite URL, or raw calendar-event identifier. An interruption between saving the acknowledgment and displaying the prompt can suppress that occurrence rather than replay it. Reminder monitoring pauses if durable acknowledgment or native display cannot be established. No event content is logged, added to diagnostics, retained in history, or sent to a server by this feature; an explicitly started recording still produces normal capture data. macOS account synchronization still contacts the configured calendar provider independently of Murmur.

Murmur transcribes on this Mac with a separately downloaded Whisper model. It does not need an account, telemetry service, or cloud transcription to use the core features. The initial model download contacts its configured model host. Starting with v0.1.2, Murmur checks GitHub Releases for updates at launch, at most once a day, and whenever you choose Check for updates. Like any web request, this lets GitHub see your IP address. An update downloads only when you choose Update. Manual installer downloads also use GitHub Releases. Clicking an external privacy/report link opens a browser. Do not assume that visiting third-party hosts is anonymous.

Dictation may temporarily use the macOS clipboard to insert text into the foreground app; this can replace clipboard contents, and paste into the wrong field if the target changes within the same app. Murmur attempts guarded restoration, but macOS cannot guarantee atomic restoration against a concurrent clipboard writer. Dictation history and meeting transcripts are stored locally; successful meeting audio is retained inside Murmur for recovery for at most 7 days (you choose the window), while failed or interrupted recordings are kept until you retry, save a copy or delete them. Generated Markdown and independently saved audio copies can remain after deleting a meeting. A crash can leave temporary audio until later cleanup. Other apps, macOS backups and external files are outside Murmur's deletion controls.

Microphone and Accessibility permissions enable recording, hotkeys and paste automation; Input Monitoring is requested as a shortcut fallback when needed. Meeting/system audio capture may require additional macOS permissions and participant consent. Ask everyone involved before recording; local law and workplace policy may apply. Settings → About offers **Preview diagnostics**: generation is opt-in, the report is shown locally before copying, and nothing is uploaded automatically. Review any copied report again before sharing it; never post recordings, transcripts, keys, device identifiers or personal data to public GitHub issues.

The onboarding Privacy policy link opens this document in Murmur's public GitHub repository in a browser and requires an internet connection. The About report link is separate. This file is included with the source repository, not an offline page bundled into the installed app.
