# Build from source (macOS)

For the official signed/notarized installer, use the download link in [README.md](../README.md). Commands here create development builds; they do not automatically establish trusted release artifacts. Murmur requires Apple Silicon macOS 14.4+. Installed release checks were performed on macOS 27.0.1; older versions in that range remain unverified. Intel Macs, Windows and Linux are not supported; portable Rust checks on Linux do not establish app support.

Requirements: full Xcode with command-line tools, Rust 1.95.0 (`rust-toolchain.toml`), Node 22 or 24 (Node 24 used for the full local unit suite), Corepack and pnpm 10.32.0 (`packageManager` in `package.json`). Install the target/toolchain and native dependencies required by Tauri 2 and whisper.cpp/Metal. On macOS run:

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm legal:inventory:check
corepack pnpm test:unit
corepack pnpm test:release-metadata
corepack pnpm check:release-metadata
corepack pnpm build
corepack pnpm tauri dev
# Optional unsigned local app for development only:
corepack pnpm build:app-local
```

The notice generator shells out to `pnpm`, so expose the Corepack pnpm shim on `PATH` if your Corepack installation does not do so automatically. The macOS build checker verifies the separately bundled MIT LICENSE and third-party notices. Do not distribute an unsigned local app/DMG as an official installer. The release installer passes strict signature, exact-entitlement, notarization/staple and Gatekeeper checks. Fresh onboarding and a retained-data update between release candidates were tested on the stated Mac; this does not validate every legacy-data migration, failure/recovery path or supported macOS version.

For the calendar connection checkpoint, build a separate locally signed app with `corepack pnpm tauri build --debug --bundles app --config src-tauri/tauri.debug.conf.json`. Open `src-tauri/target/debug/bundle/macos/Murmur Debug.app`, then Settings → General → Meeting captures → Calendar accounts → Connect calendars. This uses the existing debug bundle ID and its own app data, not the installed production app. Select email-labelled accounts; each selection includes all calendars in that account, including newly synced ones. Nothing is selected by default, and account/source ID choices are saved locally. EventKit sources without an unambiguous email label are not listed. Earlier per-calendar debug choices are not converted into account-wide selection; reselect accounts once. Verify the system calendar grant and account selection. After connection the header has only Manage accounts; the expanded panel contains email account checkboxes, Refresh and Disconnect calendars. No meeting preview is shown, and account management reads no events. Confirm that selected account choices survive disconnect/reconnect and app restart. Do not reset existing permissions or copy production app data into the debug identity. Automated tests do not establish account synchronization or signed-app EventKit permission behavior. Meeting reminders remain off by default. To exercise the reminder-to-recording loop, select accounts and enable Meeting reminders, then create a real calendar event starting 2–3 minutes in the future with a supported meeting link in a selected account. Choose Reminder timing (At meeting start, 15 seconds, 30 seconds or 1 minute before; default 15 seconds). Keep the Mac awake and Murmur running; confirm the meeting has synced into Apple Calendar before its reminder deadline, then check that the top-right prompt appears near the selected time. Known meeting deadlines wake the native scheduler between its regular 15-second calendar refreshes; macOS sleep or delayed account synchronization can still delay or suppress an offer. Check Dismiss, repeat suppression after restart, and Start recording into the existing recording flow (including prerequisite/setup fallback). Without the speech model downloaded, the recording dialog should identify the speech model requirement, keep Start recording disabled and offer Set up model → Settings → Speech model. Download it there, then retry recording without restarting the app. Confirm that disabling reminders or Disconnect closes a pending prompt, and no prompt starts recording by itself. Reopen Settings, turn reminders off, and verify that Manage accounts remains available, with Disconnect calendars inside its expanded panel, account choices are retained, and reminders can be turned on again without reconnecting. Disconnect clears the saved connection; merely leaving Settings clears the in-memory account directory, not the connection. The reminder uses the current capture flow’s default recording title. Cancellation/rescheduling, sleep/wake, concurrent capture and a signed-app recording handoff need actual installed-app QA; unit tests do not establish those end-to-end behaviors.

At first run, grant the macOS permissions requested for the features you use. The speech model download requires a network connection and disk space (~488 MB for the current model); transcription runs offline afterward. To build a release, independently review third-party rights and the exact artifact, sign/notarize/staple with owner-controlled credentials, verify on clean Macs and test upgrades. Do not assume a new locally built artifact is covered by the QA of the published binary. In-app updates read `latest.json` from the latest GitHub Release. After notarizing and stapling the release app, run `corepack pnpm release:update-package --app <path>/Murmur.app`: it archives that exact app, signs the archive with the updater key (default `~/.tauri/murmur-updater.key`, password read from the `murmur-updater-key` login keychain item unless `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` is set), verifies the signature against the public key in `tauri.conf.json` and writes `latest.json` with that version's CHANGELOG notes. Upload the archive and `latest.json` to the GitHub Release alongside the DMG. Before relying on a release's update, install the previous version and confirm it offers, downloads and installs the new one. Before publishing v0.1.4, test an in-place update of an existing v0.1.3 installation with previously granted Microphone, Accessibility, System Audio Recording and Documents access: confirm those grants, the recording-notice setting (if previously acknowledged), the speech model and existing user data remain intact. Calendar reminders must remain off by default for existing users, and no calendar access prompt should appear until Connect calendars is clicked. Signed-debug functional QA does not replace this production-identity upgrade check. Do not reset permissions or clear app data for this test. Keep the updater private key and its password safe: without them, installed copies cannot accept future updates.
