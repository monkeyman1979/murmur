# Build from source (macOS)

For the official signed/notarized installer, use the download link in [README.md](../README.md). Commands here create development builds; they do not automatically establish trusted release artifacts. Murmur requires Apple Silicon macOS 14.4+. Installed release checks were performed on macOS 27.0.1; older versions in that range remain unverified. Intel Macs, Windows and Linux are not supported; portable Rust checks on Linux do not establish app support.

Requirements: full Xcode with command-line tools, Rust 1.95.0 (`rust-toolchain.toml`), Node 22 or 24 (Node 24 used for the full local unit suite; on Node 25+ run the unit suite with `NODE_OPTIONS=--no-experimental-webstorage`, because Node's built-in `localStorage` otherwise shadows the test DOM's and storage-backed tests fail), Corepack and pnpm 10.32.0 (`packageManager` in `package.json`). Install the target/toolchain and native dependencies required by Tauri 2 and whisper.cpp/Metal. On macOS run:

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm legal:inventory:check
corepack pnpm test:unit
corepack pnpm test:release-metadata
corepack pnpm check:release-metadata
corepack pnpm build
corepack pnpm tauri dev
# Optional unsigned local app for development only:
corepack pnpm build:app-local
```

The notice generator shells out to `pnpm`, so expose the Corepack pnpm shim on `PATH` if your Corepack installation does not do so automatically. The macOS build checker verifies the separately bundled MIT LICENSE and third-party notices. Do not distribute an unsigned local app/DMG as an official installer. The release installer passes strict signature, exact-entitlement, notarization/staple and Gatekeeper checks. Fresh onboarding and a retained-data update between earlier release candidates were tested on the stated Mac; this does not validate the v0.1.3 → v0.1.4 upgrade, every legacy-data migration, failure/recovery path or supported macOS version.

For the calendar connection checkpoint, build a separate locally signed app with `corepack pnpm tauri build --debug --bundles app --config src-tauri/tauri.debug.conf.json`. Open `src-tauri/target/debug/bundle/macos/Murmur Debug.app`, then Settings → General → Meeting captures → Calendar accounts → Connect calendars. This uses the existing debug bundle ID and its own app data, not the installed production app. Select email-labelled accounts; each selection includes all calendars in that account, including newly synced ones. Nothing is selected by default, and account/source ID choices are saved locally. EventKit sources without an unambiguous email label are not listed. Earlier per-calendar debug choices are not converted into account-wide selection; reselect accounts once. Verify the system calendar grant and account selection. After connection the header has only Manage accounts; the expanded panel contains email account checkboxes, Refresh and Disconnect calendars. The Calendar access & privacy accordion is last in the calendar section and remains available before connecting. No meeting preview is shown, and account management reads no events. Confirm that selected account choices survive disconnect/reconnect and app restart. Do not reset existing permissions or copy production app data into the debug identity. Automated tests do not establish account synchronization or signed-app EventKit permission behavior. Meeting reminders stay hidden and off until an account is selected. On first-time setup, selecting the first account should enable reminders at the default 15-second timing and animate the controls into view below the picker without moving the account rows. Turning reminders off must leave those controls available while accounts remain selected; Refresh, account changes, Settings remount and app restart must respect that saved Off choice. Removing the last selection hides the controls with the same reduced-motion-aware animation, and no accounts means no event monitoring. Existing selected accounts must not be silently opted in on upgrade or Settings mount. To exercise the reminder-to-recording loop, select accounts (turn reminders on manually if a saved Off choice exists), then create a real calendar event starting 2–3 minutes in the future with a supported meeting link in a selected account. Choose Reminder timing (At meeting start, 15 seconds, 30 seconds or 1 minute before; default 15 seconds). Keep the Mac awake and Murmur running; confirm the meeting has synced into Apple Calendar before its reminder deadline, then check that the top-right prompt appears near the selected time. Known meeting deadlines wake the native scheduler between its regular 15-second calendar refreshes; macOS sleep or delayed account synchronization can still delay or suppress an offer. Check Dismiss, repeat suppression after restart, and Start recording into the existing recording flow (including prerequisite/setup fallback). Without the speech model downloaded, the recording dialog should identify the speech model requirement, keep Start recording disabled and offer Set up model → Settings → Speech model. Download it there, then retry recording without restarting the app. Confirm that disabling reminders or Disconnect closes a pending prompt, and no prompt starts recording by itself. Reopen Settings, turn reminders off, and verify that Manage accounts remains available, with Disconnect calendars inside its expanded panel, account choices are retained, and reminders can be turned on again without reconnecting. Disconnect clears the saved connection; merely leaving Settings clears the in-memory account directory, not the connection. The reminder uses the current capture flow’s default recording title. Cancellation/rescheduling, sleep/wake, concurrent capture and a signed-app recording handoff need actual installed-app QA; unit tests do not establish those end-to-end behaviors.

Recording feedback can be configured independently for dictation and meetings in Settings → General → Recording feedback (with Sound cues; Appearance keeps only the app's own theme and shell). The Floating and Notch previews share one fixed height so switching style never shifts the page. Each has a Floating / Notch selector. Floating uses a visual six-position screen picker (top/bottom left/center/right) and the existing 20-point inset from usable screen edges, excluding the menu bar and Dock. Existing users remain Floating at their saved positions; new users default to bottom-center. Switching styles retains each floating position. Changes apply when the next recording starts. On a notched target display, Notch sits at the physical top/menu-bar level. Its two compact wings use measured camera width/depth and keep the center housing empty; the meeting notch gives a hover cue, and click or vertical scroll over the panel expands/collapses details below the camera. With Notch selected independently for dictation or meetings on an external notchless display, that capture type’s saved floating position is used there and a matching notch surface also appears at the available laptop notch. For dictation it is a read-only, click-through status mirror. For meetings it is a full controller (`meeting-notch` window and capability: exactly the meeting controller's recording commands, no dragging): it accepts first clicks, expands by click or scroll and can pause, resume, finish or discard, so a selected Notch always works whichever display the meeting started on. Both show the same session state and hide together; laptop-targeted capture uses only one notch surface. Presentation and alignment listeners target their own WebviewWindow explicitly, so a laptop mirror or meeting update cannot give an external floating pill notch styling. Floating-only mode does not enable the mirror. Expanded meetings use a compact borderless status row, a subtle keyboard-accessible Discard recording text action with confirmation, then labeled Pause/Resume and Finish actions. These sections use fixed 8-point gaps instead of distributing spare height; an explicit collapse button remains available. One persistent, consistently sized elapsed timer stays in the notch header in both compact and expanded states; it is not duplicated or enlarged in the body. The floating controller remains unchanged. Notch wings keep 16-point outer padding as the panel grows, with the camera column unchanged. The header keeps a fixed layout width; composited translations move its contents instead of re-laying out text and SVGs on every frame. Screen-reader status is outside the animated clipping tree, and meeting status contains no hidden duplicate styled recording dot. Opening uses a restrained spring-like animation with reduced-motion support. Closing uses monotonic easing, a fixed header/body layout and stable side content; native window shrink waits for the renderer’s guarded completion acknowledgement (with a lost-view failsafe) rather than racing the CSS transition. Every notch resize uses its original measured camera anchor and an even-sized native canvas, preventing accumulated position drift from AppKit’s frame-origin rounding. In notch mode the webview keeps the expanded canvas size and is re-centered inside the window in the same main-thread step as each native resize: WKWebView repaints asynchronously and otherwise shows one stale frame pinned to the new top-left corner, which appeared as a duplicated timer and icon at the end of a collapse. Meeting indicators remain visible during size motion and fast gesture reversals. The dot, waveform and timer remain continuously visible through the final compact-resize hand-off, with paint synchronization before and after the AppKit job but no post-collapse opacity dip or crossfade. Only the compact interactive meeting notch has a hover cue: 10 points of width, 3 points of height and a soft drop shadow, without scaling the camera exclusion area, inside 12 points of transparent window headroom so the shadow is not clipped. The dictation indicator, passive mirrors and expanded controls have no hover effect. WKWebView updates CSS `:hover` only while Murmur is active, so the cue is driven by an AppKit tracking area (active regardless of the frontmost app) on the meeting window's own bounds; a second tracking area feeds pointer movement to the webview so expanded buttons show hover styles while another app is frontmost. Opening the meeting panel by scrolling while another app is frontmost asks macOS to activate Murmur, as a click does, and hands focus back to that app when the panel collapses or hides. macOS may refuse that activation; then the cursor stays an arrow (background apps cannot change the cursor) though button hover styles still work. Dictation never takes focus. The discard confirmation replaces the Discard/Pause/Finish row with a short in-place crossfade at an identical row height, so the buttons do not shift. Finish and confirmed Discard first shrink the panel into the exact camera housing (fading content, Reduce Motion: instant), then end the capture, so the native hide happens behind the physical notch; if the capture does not end, the panel is restored. Clicking outside collapses the expanded panel without changing recording, and the click is delivered normally to its target. Mouse-down-only local/global AppKit observers are installed only while expanded and removed on collapse/hide; no keyboard, global pointer-movement or global scroll monitoring is added (the meeting notch's tracking areas observe only its own window). No audio routing or volume changes are introduced. On a notchless target display the saved floating anchor is used without changing preferences. Other notch apps, including Alcove, can overlap; use Floating when running them. Floating meeting controls remain draggable and pause/resume preserves their location. Dictation keeps its focused-app display selection; meetings use the display containing Murmur’s main window. Settings labels are top-aligned and the placement diagrams do not include a hint paragraph. Installed-app QA is still required for all anchors and mixed Floating/Notch combinations, simultaneous external/laptop dictation feedback, camera clearance and menu-bar-level layering, relaunch persistence, Dock positions, mixed-scale external displays, first-click expansion without stealing dictation focus, scrolling/reduced-motion behavior, recording issues while collapsed, pause/resume and discard confirmation while expanded, and visibility in other apps’ full-screen Spaces. Automated tests do not establish those native visual behaviors.

At first run, grant the macOS permissions requested for the features you use. The speech model download requires a network connection and disk space (~488 MB for the current model); transcription runs offline afterward. To build a release, independently review third-party rights and the exact artifact, sign/notarize/staple with owner-controlled credentials, verify on clean Macs and test upgrades. Do not assume a new locally built artifact is covered by the QA of the published binary. In-app updates read `latest.json` from the latest GitHub Release. After notarizing and stapling the release app, run `corepack pnpm release:update-package --app <path>/Murmur.app`: it archives that exact app, signs the archive with the updater key (default `~/.tauri/murmur-updater.key`, password read from the `murmur-updater-key` login keychain item unless `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` is set), verifies the signature against the public key in `tauri.conf.json` and writes `latest.json` with that version's CHANGELOG notes. Upload the archive and `latest.json` to the GitHub Release alongside the DMG. Before relying on a release's update, install the previous version and confirm it offers, downloads and installs the new one. Before publication, test an in-place update from the previous release with previously granted Microphone, Accessibility, System Audio Recording and Documents access: confirm those grants, the recording-notice setting (if previously acknowledged), the speech model and existing user data remain intact. For v0.1.4, the maintainer explicitly authorized publishing the verified artifacts first and testing the installed v0.1.3 updater afterward; until that test is confirmed, installed-system upgrade and data/permission retention remain unverified. Calendar reminders must remain off by default for existing users, and no calendar access prompt should appear until Connect calendars is clicked. Signed-debug functional QA does not replace this production-identity upgrade check. Do not reset permissions or clear app data for this test. Keep the updater private key and its password safe: without them, installed copies cannot accept future updates.
